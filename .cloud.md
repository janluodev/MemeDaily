## Current Architecture

- ADR-012 makes both canonical data validators apply one shared, pure continuity rule to their own
  filename inventory. The bounded interval begins on 2026-07-26 and ends at that feed's
  maximum existing date; pre-cutoff history and the other feed's maximum are irrelevant.
- ADR-011 bounds manually authorized historical candidates to 2026-07-26 through Shanghai
  today. Both trusted workflow jobs independently require a historical target to be absent
  on `main`; same-day minimum repair/migration remains unchanged, and historical overwrite
  is impossible through this path.
- Next.js static export serves two git-backed feeds at `https://memedaily.fun`:
  memes in `data/daily/` and everyday-life news in `data/daily-news/`.
- Eight ChatGPT Work Web Scheduled Tasks own unattended schedules and read current
  rules/data from GitHub on every run. They cover news at 06:00, hourly 07:15–12:15,
  14:45, and 21:30, and memes at 07:00, hourly 08:00–13:00, 14:30, and 21:20, all in
  Asia/Shanghai. They submit one exact daily JSON on
  `codex/daily-{meme|news}-YYYY-MM-DD` and open a same-repository PR. Their eight
  persistent prompts were updated and directly read back from Scheduled Tasks. A cheap
  terminal no-op requires the exact current feed policy, `published`/`partial`, three
  to ten evidence-qualified items, matching reported/visible counts,
  `editorial_complete: true`, and the complete feed contract. Legacy policy is
  migration work, `held` is operator-only, and fallback cannot publish `skipped`.
- Codex Desktop heartbeat automations are not Cloud schedules and are not part of the
  availability path. The repository contract requires every fixed catch-up to start
  with an inexpensive live-main completion preflight and stop before research/mutation
  only for a current-policy, editorially complete, fully valid three-to-ten-item
  envelope; updating all eight external persistent prompts to that contract is
  complete.
- `codex-daily-pr-publish.yml` never checks out the PR tree. A read-only job fetches
  only the JSON blob and validates with trusted main code; a separate trusted job
  stamps, revalidates, rebases, pushes, and waits for correlated Pages success.
- Repository ruleset `codex-trusted-main` is the credential boundary: Cloud-connected
  tools and ordinary users cannot update/merge main; one Actions-secret-backed write
  deploy key is the sole bypass and appears only in trusted final push steps.
- Old Anthropic publishers, GitHub cron, catch-up dispatchers, and external cron
  ownership are retired. Fallback/monitor workflows are manual disaster recovery.
- Public-web content is untrusted data. No login cookies, private APIs, anti-bot
  bypass, copied media, private data, or paid model API is part of the product.

## Implemented Hardening

- Production dependency audit is zero after refreshing transitive `nanoid` from
  3.3.16 to 3.3.18. `audit:prod` is now the first step of canonical `npm run check`,
  so candidate validation, final rebased trusted writes, fallback, CI, and Pages all
  enforce the same high-severity release gate under Node 22/npm 10.
- Pages build has read-only contents permission; only deploy receives Pages/OIDC writes.
- Pages correlation adopts the deploy-key push run when it appears, falls back to one
  explicit dispatch only when needed, retries transient failures, and returns success
  only for a run covering the accepted SHA (or descendant) with conclusion `success`.
- Its 75-minute per-run correlation budget and 180-minute writer budget cover the
  configured 35-minute Pages job maximum, one predecessor, and one bounded recovery.
- Fallback uses live-main sync, strict date/path containment, shared writer
  concurrency, post-rebase full checks, and an explicit `HEAD:main` push.
- Monitors read live main and verify Pages freshness; empty DailyNews input now fails.
- Reader client payloads use a public meme projection; internal editorial fields remain
  server/repository only. Detail pages now expose canonical/OG/Twitter metadata.
- ADR-007 and `ai/prompts/CODEX_CLOUD_RUNBOOK.md` define the active operational contract.
- ADR-008 introduced the minimum-three availability state, bounded recovery ladder,
  and one monotonic trusted repair exception for an exact under-minimum daily file.
- ADR-009 defines the post-2026-07-27 meme score/activity model: at least 30 candidates,
  no fixed cross-day quota, stable full-history recurrence identity, post-selection
  activity, auditable candidate outcomes, strictest-sufficient tiers, Top-N capacity,
  and privacy-minimized safety drops.
